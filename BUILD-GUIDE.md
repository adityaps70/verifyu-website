# VerifyU site revamp — build guide for page authors

You are building ONE OR MORE PAGES of a static multi-page site in `/home/claude/verifyu`. The homepage (`src/pages/home.mjs`) is the reference for quality, tone and technique — read it first, and read `src/lib.mjs`, `src/styles/site.css`, `src/styles/pages.css`, `src/js/site.js` before writing anything. Do NOT edit those shared files (except appending to `pages.css` is forbidden too — put page-specific CSS in your page module's `css` export). Do not touch other people's page files.

## How a page module works
Each file in `src/pages/<name>.mjs` exports default an object (or an array of objects):
```js
import { SITE, icons, stores, device, checks, check, note, flag, sectionHead, featureCard, accordion, railNav, pageHero, ctaBand, finalCta, breadcrumbLd, faqLd } from '../lib.mjs';
export default {
  path: '/features',          // URL (no trailing slash). Nested: '/organisations/hospitals', '/legal/privacy'
  nav: '/features',           // which top-nav link is "current" (use the top-level href: '/how-it-works', '/rewards', '/about'; dropdown pages: leave '' )
  title: 'Features',          // becomes "Features | VerifyU"
  description: '…',           // unique meta description, 140–160 chars, no keyword stuffing
  body: `<section …>…</section>`,   // HTML placed inside <main id="main">
  css: `…`,                   // OPTIONAL page-specific CSS, scoped with a unique prefix (e.g. `.ft-`), appended to site.css
  jsonld: breadcrumbLd([{name:'Home',path:'/'},{name:'Features',path:'/features'}]),  // optional; can be an array of LD objects
  priority: 0.8,              // sitemap priority (optional)
};
```
Build & preview: `cd /home/claude/verifyu && node build.mjs` (dist/), local server already running at http://localhost:8787 (if not: `cd dist && python3 -m http.server 8787 &`).
QA: `node walk.mjs /your-path name 1440 3` then Read `/tmp/shots/name-sheet.jpg` (split it with PIL if tall); `node walk.mjs /your-path name-m 390 4` for mobile; `node /tmp/ov.mjs /your-path` lists horizontal-overflow culprits (must be empty; sw must equal 390). Also run at 900px (tablet). Fix everything you see. Check console/HTTP errors in the walk output.

## Components (lib.mjs)
- `pageHero({eyebrow, title, lead, ctas, media, dark})` — page top. `title` can contain `<br>`. `ctas` is HTML of buttons. `media` optional (`device(...)` or a `<figure class="photo …">`). Use `dark:true` for serious/enterprise pages.
- `sectionHead({eyebrow, title, lead, center})` — section intro with reveal.
- `device({src, alt, cls, inner, id})` — iPhone mock. Real screenshots (demo data) in `/images/app/`: home-dashboard, home-emergency, profile-personal, profile-medical-otp, profile-emergency, face-verification, sos, steps, settings, recharge (all 722×1600, face 736×1600) plus `/images/verifyu-registration-poster.jpg` (registration start, 478×850) and the video `/videos/verifyu-registration.mp4`. `cls`: `is-sm` (260px) / `is-lg` (400px) / `is-flat` (lighter shadow). For UI states with no screenshot, use `inner` with the `.ui*` classes (see home.mjs `uiInfo`, `uiPeople`, `uiScan`) — restrained, brand-coloured, never futuristic.
- `stores(cls)` store badges (`'is-light'` on light backgrounds if you want the white variant). `SITE.play`, `SITE.appstore`, `SITE.email`, `SITE.whatsappHref`, `SITE.whatsapp`, `SITE.entity`.
- `checks([...])`, `note('…')` (small info line), `flag('Owner verification')` — a visible amber badge meaning "needs owner/legal confirmation"; use it inline after any statement you could not verify (see Claim safety).
- `featureCard({icon, title, body, iconCls, href})`, `accordion([{q,a,id}], 'single')`, `railNav('id')` + `<div class="rail" data-rail="id">` for snap carousels.
- `ctaBand({title, copy, primary:{t,h,ext}, secondary:{t,h}, dark})` — compact CTA strip. `finalCta({headline, copy})` — the cinematic dark ending with phone; most consumer pages should end with `finalCta()`; organisation/partner pages end with a `ctaBand` whose primary is their specific CTA (no app download push).
- Icons: `icons.face, scan, phone, heart, medical, sos, shield, users, user, pin, steps, coin, recharge, share, building, hospital, gov, school, event, work, home, senior, eye, lock, log, bell, play, mail, chat, globe, car, plane, crowd, child, memory, instagram, linkedin, qr, search, doc, trash, flagIcon, handshake, star, fitness, arrow, arrowUpRight, chevron, check, plus, info`.

## CSS you can use (site.css / pages.css)
Typography: `.display .h1 .h2 .h3 .h4 .eyebrow .lead .body .small .meta .num .grad-text .muted`. Layout: `.container (.is-narrow .is-wide) .section (.is-tight .is-dark.on-dark .is-cloud .is-warm .is-purple) .section-head .grid .grid-2/3/4 .split > .col-5/6/7 .row .stack .mt-1..6 .center .hr`. Controls: `.btn .btn-primary .btn-ink .btn-white .btn-ghost .btn-sm .btn-lg .link .link-ink .pill (.is-teal .is-sos .is-ink .is-ghost)`. Cards: `.card (.is-xl .is-cloud .is-dark .is-static .is-flat) .icon (.is-teal .is-blue .is-sos) .check .checks .note .flag`. Patterns in pages.css: `.showcase/.showcase-phone/.showcase-list/.showcase-item` (pinned-phone feature showcase), `.timeline/.tl-item/.tl-btn` (step timeline with `data-seek` chapter buttons), `.video-wrap` (+ `data-video`, `data-video-wrap`, `data-video-play`), `.plans/.plan(.is-featured)/.price/.save`, `.track/.track-grid/.track-cols/.track-col` (organisation tracks), `.team-grid/.leader`, `.press-card/.press-outlet`, `.search/.topics/.cats/.faq-actions/.contact-card` (help centre), `.trust-grid/.trust-section/.trust-kv`, `.legal-grid/.toc/.prose`, `.role-card`, `.stat`, `.band`, `.photo (.is-4x5 .is-3x2 .is-1x1 .is-16x9) .cap`, `.table/.table-wrap .yes .no`, `.tabs` (with `data-tabs`, buttons `role="tab" aria-controls`, `<span class="ind"></span>`), `.marquee/.marquee-track/.press-item`, `.ring` (+ `data-count`), `.coin`, `.flow`, `.glow`.
Motion attributes handled by site.js: `data-reveal` (`="fade" | "scale" | "left" | "right"`), `data-stagger` (children stagger), `.mask > span` masked line reveal inside a `.mask-group`, `data-count="10000"`, `data-story data-steps="N"` + `data-step-item="i"` / `data-step-panel="i"` (sticky scroll story, see home.mjs), `data-switch` + `data-switch-btn/panel` (auto-cycling phone states), `data-tracks` + `data-track/data-track-panel`, `data-accordion`, `data-tabs`, `data-rail`, `data-crossfade` (children `<img>` crossfade; add `.is-active` on first), `data-faq-search`, `data-price-toggle` etc. Everything respects prefers-reduced-motion automatically. Use motion deliberately (2–3 reveals per section), never decorative floating icons, no scroll-jacking.

Design rules: white/cloud backgrounds, purple structural, ONE dark section per page at most (two on long pages), gradient text only in a hero, teal = success/verification, RED ONLY for SOS/emergency elements (`.icon.is-sos`, `.pill.is-sos`). 20–30px radii, soft shadows, big breathing room, sentence case (not uppercase) except `.eyebrow`/`.meta`. Headlines short and concrete; alternate EMOTION → FACT → PRODUCT PROOF → VISUAL → CTA. Avoid the old site's precious phrasing ("A little…", "One shared…", "A good question…"). Body copy ≤ 60 characters per line, short paragraphs. Every page must have exactly one `<h1>` (pageHero provides it), semantic `<section aria-labelledby>` where it makes sense, `alt` text on images, 44px targets, no hover-only content.

## Claim safety (hard rules)
Never invent users, downloads, ratings, awards, partners, hospital or government adoption, response times, certifications, encryption claims, cases or statistics. Never say guaranteed, instant rescue, always works, 100% secure, foolproof, end-to-end encrypted. Use: helps, can support, designed to, aims to, where available, subject to access, subject to app version/plan. When a page needs a statement you cannot verify (e.g. exact retention period, whether the app supports in-app account deletion, whether a hospital dashboard exists, exact data processors), write the most defensible version and append `${flag()}`; keep a short list of every flagged item in your final report. VerifyU supports identification and communication; it does not replace emergency services.

## Content admin (added September 2026)

Editable content lives in `content/*.json` — `team.json`, `advisory.json`, `partners.json`, `articles.json` — and uploaded images in `public/images/uploads/`. `src/content.mjs` reads them at build time, so the public site stays fully static.

- `node admin/server.mjs` (or double-click `start-admin.command` / `start-admin.bat`) starts the admin at http://127.0.0.1:8790 and a site preview at :8791. First run asks for an admin password (stored as a scrypt hash in `admin/config.json`, which is git-ignored).
- The admin edits the JSON files, uploads images, and "Publish changes" runs `node build.mjs`, then the optional deploy command from Settings (or `ADMIN_DEPLOY_CMD`).
- Pages that read content: About (team grid, advisory board section — hidden when empty), Home (leadership carousel), Partners ("Partners we work with" — hidden when empty), Blog (`/blog` + `/blog/<slug>` — generated only when at least one article is published; the nav and footer link appear then too).
- To expose the admin on a server: `ADMIN_HOST=0.0.0.0 node admin/server.mjs` behind an HTTPS reverse proxy. Never expose it over plain HTTP.
